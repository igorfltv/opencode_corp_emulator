# Эмулятор сервера для корпоративного OpenCode

Локальный backend для проверки [корпоративного плагина OpenCode](https://github.com/igorfltv/opencode_corp). Он даёт тестовый вход в браузере, версионированный конфиг, каталоги skills и MCP по роли, светофор нагрузки и фиксированный ответ макета inference API. Реальные SSO, Jira, Confluence и LLM здесь не используются.

Проверенная связка: **Bun 1.3.14**, **OpenCode 2.0.24**, плагин `github:igorfltv/opencode_corp#main`. Для запуска сервера нужен только Bun: у этого репозитория нет npm-зависимостей.

## Запуск на своём компьютере

1. Убедитесь, что Bun установлен: `bun --version`.
2. Склонируйте проект и запустите сервер:

   ```sh
   git clone https://github.com/igorfltv/opencode_corp_emulator.git
   cd opencode_corp_emulator
   bun run start
   ```

3. В другом терминале проверьте ответ:

   ```sh
   curl http://127.0.0.1:4310/health
   # {"ok":true,"emulator":true}
   ```

4. Откройте панель управления: <http://127.0.0.1:4310/admin>. Остановить сервер можно через `Ctrl+C`.

Сервер слушает только `127.0.0.1`. Состояние хранится в памяти: после перезапуска ревизия, нагрузка и журнал сбрасываются, а старые токены перестают действовать. Потребуется новый `/login`.

Если порт `4310` занят (например, прежним `bun run demo` из репозитория плагина), остановите тот процесс. Для другого порта запустите `PORT=4311 bun run start` и передайте плагину адрес `http://127.0.0.1:4311` через `CORP_SERVER_URL` при запуске OpenCode или через `options.serverURL` в записи плагина. Адрес панели тоже изменится на `http://127.0.0.1:4311/admin`.

## Подключение плагина в OpenCode

В `~/.config/opencode/opencode.jsonc` добавьте GitHub-плагин в существующий массив `plugins`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["github:igorfltv/opencode_corp#main"]
}
```

Это минимальный пример; свои остальные настройки сохраняйте. Для обычного запуска на порту `4310` дополнительных настроек нет. Если нужен другой порт, запись плагина может быть объектом:

```jsonc
{
  "plugins": [
    {
      "package": "github:igorfltv/opencode_corp#main",
      "options": { "serverURL": "http://127.0.0.1:4311" }
    }
  ]
}
```

Перезапустите OpenCode после первого подключения плагина или изменения адреса. В списке slash-команд должны появиться `/login`, `/refresh_config`, `/skills_load`, `/mcps_load`, `/inference_status`, `/corp_status` и `/logout`. Если команды не видны, проверьте, что OpenCode загрузил GitHub-плагин, конфиг читается из ожидаемого профиля, а версия OpenCode совместима с API плагина. Сервер должен работать всё время теста.

## Полный сценарий проверки

1. В OpenCode выполните `/corp_status`, затем `/login`. Откроется браузерная страница с выбором фиктивной учётной записи. Выберите **Анна · Engineering** и нажмите «Войти». Пароль не требуется. После возврата в OpenCode повторите `/corp_status`: появятся пользователь и ревизия конфига.
2. Выполните `/skills_load`. Отметьте skills во встроенной форме OpenCode. У Engineering доступны три skills; у **Михаил · Analytics** доступен только `corp-data-quality`. Загруженные файлы появятся в `~/.config/opencode/skills/corp-*/SKILL.md` (или в папке выбранного профиля).
3. Выполните `/mcps_load`. У Engineering доступны тестовые Jira и Confluence, у Analytics — только Confluence. Выберите MCP во встроенной форме. В локальной браузерной странице введите `demo-jira-token` для Jira или `demo-confluence-token` для Confluence. **Настоящие PAT в эмулятор не вводите.** Встроенная команда `/mcps` покажет статус подключения. Для замены токена снимите выбор MCP и выберите его снова.
4. В панели эмулятора измените название модели и нажмите «Опубликовать версию». Выполните `/refresh_config` и проверьте обновление `providers.corporate` в `opencode.jsonc`. Плагин также проверяет конфиг автоматически **раз в час**.
5. В панели нажмите «Перегрузка». Выполните `/inference_status`; плагин покажет красный статус. При обычной работе он опрашивает нагрузку каждые **30 секунд** и уведомляет при смене цвета. Кнопки «Норма» и «Высокая» дают остальные состояния.
6. Нажмите «Включить сбой». `/inference_status` покажет недоступность API, а ранее применённый конфиг останется. Восстановите API. Кнопка «Завершить» в блоке «Тестовые сессии» инвалидирует токены: после неё повторите `/login`.
7. Выполните `/logout` и проверьте, что корпоративный провайдер удалён из `opencode.jsonc`, а токены MCP удалены из профиля.

Для быстрой демонстрации фонового обновления можно запустить OpenCode с `CORP_REFRESH_INTERVAL_MS=10000` и `CORP_LOAD_INTERVAL_MS=2000` либо передать плагину `options.refreshMs` и `options.loadPollMs` с теми же значениями. Это настройки **плагина**, не эмулятора; по умолчанию остаются 1 час и 30 секунд.

## Проверка inference API

После `/login` в списке моделей доступна `corporate/demo-code`. Эмулятор поддерживает `GET /v1/models` и `POST /v1/chat/completions`, включая потоковый ответ, но всегда возвращает фиксированное сообщение. Качество генерации и реальные затраты на инференс этим тестом проверить нельзя. Токен нужен и для этих запросов; его не следует вставлять в инструкции или журнал терминала.

## Автоматические тесты

```sh
bun run test
```

Тесты поднимают сервер на свободном loopback-порту и проверяют браузерный вход с PKCE, одноразовость кода, `ETag`/публикацию конфига, права на skills и MCP, светофор, фиксированный inference-ответ, защиту admin API, сбой, истечение и отзыв токена. Установленный OpenCode для них не нужен. Для проверки команд самого OpenCode используйте полный сценарий выше.

## Что делает панель и API

| Адрес | Назначение |
|---|---|
| `GET /health` | Проверка запуска без авторизации. |
| `GET /admin` | Локальная панель: конфиг, нагрузка, сбои, завершение сессий, журнал действий. |
| `/oauth/requests`, `/oauth/authorize`, `/oauth/approve`, `/oauth/token`, `/oauth/revoke` | Демонстрационный вход по одноразовому коду и PKCE. |
| `GET /api/config` | Корпоративный конфиг с ревизией и `ETag`; поддерживает `If-None-Match`. |
| `GET /api/skills`, `GET /api/skills/:id` | Каталог и содержимое skills с проверкой роли. |
| `GET /api/mcps` | Каталог MCP с проверкой роли. |
| `POST /mcp/jira`, `POST /mcp/confluence` | Макеты MCP с одним read-only инструментом; принимают только соответствующие тестовые токены. |
| `GET /api/load` | Текущий цвет светофора, очередь и текст статуса. |
| `/v1/models`, `/v1/chat/completions` | Макет OpenAI-совместимого inference API. |

Панель доступна только на loopback-адресе и не требует корпоративного пароля. Не открывайте её наружу через proxy или проброс порта. Это тестовый сервер: пользователи фиктивные, состояния не переживают перезапуск, а вход не заменяет рабочий OIDC/SSO.
